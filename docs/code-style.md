# 代码与注释约定

本项目对外公开，代码会被反复审阅。约定只有一条原则：**每一处设计都留下可复核的依据**，
注释写判断与取舍，不写对话。

## 注释

- 只写三类信息：**为什么这样做**、**不那样做会怎样**、**依据是什么**。
- 不出现第一人称与读者指称（我、我们、你、您）。需要指代实现方时写「模块侧」「注入侧」「本实现」。
- 不使用口语与情绪化表达（干脆、其实、瞎、反正、太难、太夸张之类），不使用语气词（吧、呢、嘛、啦、啊）。
- 不做现场叙述。日志证据写成「日志：字段 X 为 Y」或「日志显示 ……」，不写时间点流水账。
- 结论先行：第一句写判断，后面才写依据；长依据折成列表。
- 描述的对象必须是当前代码。功能删掉时，指向它的注释一并删掉，不留「曾经」「原来的」叙述。

## 常量与字面量

- 同一个值出现两处即提取常量；出现三处必须提取。
- 厂商系统类的全限定名统一取 `hook/OemClasses.kt`，不在各 Hook 内重复书写字符串。
- 面板尺寸、动画时长、超时阈值一类的数值，命名要带单位与语义（`SHADE_COLLAPSE_DELAY_MS`、
  `MAX_APPEND_ACTIVITIES`），禁止裸数字直接出现在判断里。

## 反射

- 统一走 `hook/OemReflection.kt`，不在各文件重复实现字段/方法查找。
- 需要区分两种查找语义：
  - `call` / `findMethodByArity`：按参数个数定位，适用于同名方法只有一个重载的场景；
  - `findMethod`：按精确参数类型定位，适用于 `Task.resize` 这类重载密集的方法。
- 取不到值时返回 `null`，由调用方决定降级或记录 WARN；只有「缺了就无法继续」才用
  `requireMethod` 抛异常。

## 结构

- 单个 Kotlin 文件控制在 600 行以内，单个函数控制在 120 行以内。
- 一个 Hook 类只承担一件事；同一文件内出现多个独立职责时按职责拆分。
- 状态机、几何计算、反射访问三类逻辑分开：前两者应可在 JVM 单测中直接验证（见 `app/src/test`）。
- 超过阈值的存量文件（`ColorOsFreeformCoordinator`、`OutsideTapCloseHookInstaller`、
  `CornerRadialOverlayView`、`ActivityStarterZoomInjector`）在改动其功能时顺带拆分，不为拆而拆。
